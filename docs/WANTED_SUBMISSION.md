## 3. 폼에 맞춰 사용할 소개문

### 프로젝트명

과학SOS · 교사 감독형 학습지원

새 다과목 화면의 이름은 학습SOS이다. 제출 제목은 팀이 정한 이름으로 통일하고 저장소 이름 `science-sos`는 유지한다.

### 한 줄 소개

같은 오답 뒤의 서로 다른 이유를 읽고, 교사가 고른 확인 활동을 거쳐 학생이 설명을 다시 쓰게 하는 학습지원 도구입니다.

### 해결하려는 문제

학생이 같은 답을 골라도 이유는 다릅니다. 과학에서 ‘무거우면 가라앉는다’는 설명은 질량만 보거나 액체의 조건을 빠뜨린 결과일 수 있고, 수학에서 분모가 큰 분수가 더 크다는 설명은 자연수 크기의 규칙을 그대로 적용한 결과일 수 있습니다. 정오만 집계하면 학생에게 다음으로 어떤 질문과 활동이 필요한지 알기 어렵습니다. 교사가 모든 이유와 변화 과정을 읽어 수업에 연결하는 데에도 시간이 듭니다.

### 해결 방식

학생은 답과 이유를 짧게 남깁니다. AI가 원문에서 가능한 설명 유형과 근거를 제안하면 교사가 이를 보고 보완 질문, 확인 활동 또는 이해 확인을 선택합니다. 학생은 승인된 활동을 수행하고 설명을 수정한 뒤 새로운 조건의 문항에 답합니다. 교사는 최초 설명과 수정 설명, 전이 응답을 함께 보고 다음 피드백을 결정합니다.

새 학습 경로에는 과학의 질량·밀도 비교와 수학의 단위분수 막대 비교를 콘텐츠 팩으로 구현했습니다. 공통 흐름을 유지하면서 과목에 맞는 활동을 제공합니다. 팩의 범위·정답·루브릭·활동은 교사가 검토해야 학급에 배정됩니다.

### AI 활용 방식

AI의 역할은 학생 이유에 대한 가설과 원문 근거를 제안하는 것입니다. 자동 성적이나 확정 진단을 내리지 않고, 교사가 학생 원문을 보며 다음 활동을 결정합니다. 응답 구조와 인용 구절을 코드로 확인하며, 근거가 부족하거나 분석이 실패한 경우에는 교사 검토 경로를 유지합니다.

기존 과학 교실은 Cursor CLI 워커로 분석과 자료 근거 답변을 처리하도록 구현했습니다. 확장 경로는 답안과 작업을 DB에 함께 저장하고 독립 서버 워커가 Vercel AI Gateway로 분석하도록 구성했습니다. 임대·제한된 재시도·호출 한도로 중복 처리와 무한 대기를 줄이도록 설계했습니다. 독립 워커의 운영 배포와 실제 모델 호출 확인은 코드 구현과 구분해 보고합니다.

### 자료 연결과 MCP

과목·주제 코드로 공식 학습자료 링크 후보를 찾는 공개 MCP 디렉터리를 구현했습니다. MCP에는 학생 답안·계정·학급 정보를 보내지 않으며, 후보는 교사가 내용과 접근 조건을 검토하고 전달해야 학생에게 표시됩니다. 이 디렉터리는 EBSMath·Khan Academy·PhET의 공식 링크 4개를 관리합니다. 해당 기관의 공식 MCP 연결이나 실시간 본문 검색은 아닙니다.

### 제작에 사용한 AI 도구와 기술

- OpenAI Codex: 요구사항·설계 문서 정리, 화면·API·DB·워커 구현, 테스트 작성, 오류 수정과 제출 자료 정리에 활용했습니다.
- Cursor CLI: 기존 과학 교실의 이유 분석과 자료 근거 답변을 처리하는 추론 워커에 활용했습니다.
- Vercel AI Gateway: 새 학습 워커의 모델 API 어댑터로 구현했습니다. 계정 크레딧·모델 접근권한·실제 추론 성공은 운영 확인 후 별도 기재합니다.
- Next.js·React·TypeScript, Supabase Auth·PostgreSQL, Vercel, MCP SDK와 Docker로 웹·권한·저장·자료 연결·독립 워커를 구성했습니다.

도구를 구현에 사용한 사실과 특정 모델의 라이브 호출 성공을 혼동하지 않습니다. 비용 절감률이나 크레딧 차감액은 측정하지 않았습니다.

### 차별점과 확장 가능성

학습 기록의 중심은 답안 점수가 아니라 ‘처음 생각한 이유 → 교사의 다음 질문 → 활동 → 설명 변화’입니다. 교사 승인을 데이터와 API 흐름에 포함하고, 과목별 문항·활동·루브릭을 버전이 있는 팩으로 분리했습니다. 과학과 수학의 작은 팩 두 개로 공통 구조를 구현했으며 다른 과목은 이후 각 과목 전문가의 검토를 거쳐 추가할 계획입니다.

### 현재 한계와 다음 단계

가상 학급과 합성 시험 데이터는 실제 학생 이용 실적이나 학습 효과의 증거가 아닙니다. 두 과목 팩의 교육적 적합성 검토와 실제 수업 평가는 아직 남아 있습니다. 우선 배포 환경의 로그인·모델 응답·독립 워커의 연속 실행을 확인하고, 교사와 함께 문항·활동·루브릭을 평가하겠습니다. 이후 학교 계정 관리와 개인정보 보존·삭제 운영을 갖추고 소규모 수업에서 교사 검토 시간과 학생 설명 변화를 관찰할 계획입니다.

## 4. 심사자 사용 안내 초안

현재 공개 배포를 안내할 때:

> 로그인 없이 화면을 살펴보려면 체험 화면을 이용해 주세요. 가상 학급의 학생과 교사 역할을 전환하며 예측 이유, 교사 검토, 활동과 설명 변화 흐름을 볼 수 있습니다. 체험 화면의 분석과 답변은 사전 작성된 자료입니다. 실제 수업 경로는 별도 인증·DB·워커를 사용합니다.

새 `/learn`을 배포하고 실제 전체 흐름을 확인한 뒤에는 안내를 해당 배포 URL로 교체한다. 코드만 있는 상태에서 `https://science-sos.vercel.app/learn`을 작동하는 서비스 링크라고 제출하지 않는다. 필요한 심사 계정은 공개 README에 비밀번호를 적지 않고 제출 폼이 제공하는 적절한 비공개 안내란으로 전달한다.

60초 소개 순서:

1. 같은 답을 고른 학생도 이유가 다르다는 문제를 설명한다.
2. 한 학생의 이유와 AI 제안, 교사의 검토 화면을 보여준다.
3. 승인된 활동을 거쳐 설명과 전이 응답이 바뀌는 흐름을 보여준다.
4. 교사 자료 전달과 과학·수학 두 팩의 공통 구조를 소개한다. 현재 서비스에 배포하지 않은 화면은 개발 중인 화면임을 표시한다.

## 5. 최종 제출 전 순서

- [ ] 원티드 로그인 후 참가 등록과 내 과제 상태, 필수 항목·글자 제한을 확인한다.
- [ ] 제출할 배포와 브랜치를 확정하고, 공개 링크가 실제로 제공하는 기능만 소개한다.
- [ ] 새 경로를 제출한다면 격리 환경에서 005~007 적용, 팩 등록, 워커 설정을 완료하고 실제 인증·모델 응답·교사 승인부터 학생 완료까지 확인한다.
- [ ] 실제 모델을 사용하는 경로의 워커가 심사 기간 계속 실행될 위치와 장애 대응을 정한다.
- [ ] 교사 자료 검토·전달·철회와 학생별/학급별 권한을 확인하고, 자료 디렉터리의 활성화 상태를 기록한다.
- [ ] 해당 커밋의 테스트·빌드 결과와 실제 운영 점검 결과를 각각 남긴다. CI의 합성 인증·모델 결과를 실제 공급자 성공으로 적지 않는다.
- [ ] 소개문·링크·팀 정보·사용 도구를 실제 폼에 맞춰 정리하고 최종 제출 완료 표시를 확인한다.

현재 우선순위는 새 기능을 더 늘리는 것보다 **실제로 접근 가능한 제출 경로와 AI 운영 상태를 확정하는 것**이다.

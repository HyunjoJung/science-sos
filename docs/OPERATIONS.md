## 구조

브라우저 → Next.js `/api/lab` → 사용자 세션으로 Supabase RPC 호출.
학생 제출 → DB `pending` → 이 PC의 Cursor 워커 → 실제 JSON 분석 → 교사 검토 → 승인된 고정 과학 실험 → 학생 설명 수정 → 새 문항 → 교사 루브릭.

Vercel에는 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, 배포 주소인 `APP_ORIGIN`만 설정합니다. 서비스 키와 Cursor 로그인 자격증명은 배포하지 않습니다.

로컬 워커에 필요한 값은 `.env.example` 참조. CLI 경로는 공식 Cursor 배포본의 `index.js`, Node 경로는 해당 배포본의 `node.exe`입니다. `CURSOR_WORKSPACE`는 앱·키·학생 파일이 없는 별도 디렉터리입니다. 워커는 도구 사용을 금지하고 자식 프로세스 환경에서 Supabase 키를 제거합니다. 구조화 응답과 원문 근거를 검증합니다.

```powershell
node --env-file=.env.local scripts/cursor-worker.mjs
# Windows 백그라운드 실행 및 중복 실행 방지
./scripts/start-worker.ps1
```

PC가 꺼지거나 워커가 종료되면 새 답안의 AI 분석은 대기합니다. 교사는 원문을 읽고 직접 검토할 수 있습니다. 호출 오류는 '분석 불가 · 직접 검토'로 표시하며 고정 답변으로 대체하지 않습니다. 향후 상시 운영은 별도 모델 API 키를 이용하는 서버 워커로 교체해야 합니다. Vercel AI Gateway는 카드 등록을 요구해 이번에 활성화하지 않았습니다.

## 데이터와 권한

- `lab_members`: 역할과 반. 일반 가입만으로 역할을 얻을 수 없음.
- `lab_records`: 현재 사고 기록. 직접 읽기/쓰기 차단, 세션을 확인하는 RPC만 허용.
- private 스키마: 이전 기록, 요청 중복 방지, AI 임대와 일별 요청 예산.
- 학생은 자기 기록, 교사는 자기 반만 조회. 학생 응답에서 AI 가설과 근거 노트 제외.
- 승인 전 실험 결과 조회 거부. 모든 수정은 버전 검증. 일별 AI 요청 최대 100회.
- SQL은 `supabase/migrations` 순서대로 적용. 현재 Supabase SQL Editor로 적용했으며 CLI migration history는 별도 등록하지 않았음.

## 검증

통합 검증 스크립트는 다른 학생/반 접근, 교사 권한, 승인 전 실험, 중복 요청, 오래된 버전, 누락 버전, 루브릭 null 거부, 실제 Cursor 분석, 보류·재제출·수정·재평가·완료를 검사합니다. 브라우저에서 로그인과 실제 저장된 기록을 확인합니다.

고정 과학 실험은 이상화한 시뮬레이션입니다. 실제 센서 관측이나 학생 실험 결과로 주장하지 않습니다. 통합 검증에서 만든 기록은 테스트 계정의 실행 기록이며 실제 수업 효과의 증거가 아닙니다.

## 첨부 HTML 화면 기획 반영

`science-sos.html`과 `index.html`의 동일한 화면 기획을 React 컴포넌트로 반영했습니다. 남색·민트 색상, 상단 역할 표시, 수업 선택, 교사/학생 탭, 원문 카드와 확인·수정·보류, 학생 생각 돕기 질문을 사용합니다. HTML의 가상 명단 20명·가짜 응답·가짜 채팅·브라우저 localStorage 로직은 가져오지 않았습니다. 로그인 계정의 서버 권한으로 화면을 결정합니다.

- 수업 8개: 밀도, 용해와 질량, 직렬회로, 열전달, 광합성, 달의 위상, 기체 압력, 증발. 기존 밀도 실험 3개는 유지합니다. 다른 단원은 교사 승인 후 학생이 실제 확인한 내용을 적는 탐구 활동입니다.
- 자료실: TXT·MD 여러 파일 또는 붙여 넣은 본문 저장, 본문 수정, 학생 채팅 사용 여부. PDF·DOCX·PPTX 자동 추출은 구현하지 않았으며 UI에도 지원한다고 표시하지 않습니다.
- 피드백: 담당 교사 → 개별 학생, 실제 저장 및 읽음 상태.
- 수업 채팅: 실제 Cursor 답변, 등록 자료의 정확한 원문 인용 확인. 자료 전체를 겹치는 구간으로 나눠 질문 키워드와 일치하는 상위 3개 구간을 제공합니다. 인용은 원본 자료 ID와 문자 위치를 함께 저장합니다. 의미 기반 검색은 아니므로 표현이 다른 질문의 근거를 놓칠 수 있습니다. 과거 대화는 같은 학생·학급·채팅방의 현재 질문 이전 기록으로 제한합니다.
- 외부 탐색 채팅: [PhET Density](https://phet.colorado.edu/en/simulations/density), [EBS 중학](https://mid.ebs.co.kr/main/middle), [사이언스올](https://www.scienceall.com/main)의 확인한 목록에서 AI가 안내합니다. 실시간 웹 검색은 아닙니다.
- 질문 기록: 본인은 자기 대화, 교사는 자기 반만 열람. 학생끼리 개인 채팅은 공개하지 않습니다.
- 함께 생각하기: 반별 주제·글·답글·공감 저장, 검색·단원 필터·페이지 이동.
- 학습 현황: 현재 질문에 대한 학생별 최신 실제 제출 기준. 정답/오답/모르겠음 및 설명 유형 집계. 테스트 계정의 검증 기록은 실제 학습 효과의 증거가 아닙니다.

확장 검증: `pnpm test:classroom`. 실제 등록 자료 사용 여부, 다른 반 접근 거부, 피드백 읽음, 토론 답글·공감 중복 요청, Cursor 근거 인용 답변, 단원에 맞는 활동, 관찰 기록 입력을 검사합니다. 이 명령은 실제 DB에 기록을 생성하므로 운영 점검용 조회 명령으로 실행하지 않습니다. 기존 자료는 유지하고 화면의 반복적인 테스트 표현만 정리했습니다.

## Cursor 워커 보완 · 2026-09-20

- 원문 근거가 없거나 근거 부족으로 판정된 경우에는 확정 가설을 저장하지 않고 교사 직접 검토로 넘깁니다.
- 생성과 저장을 분리합니다. 완료 RPC가 `false`이면 `stale`, 응답 유실이면 `unconfirmed`, 실제 적용이면 `applied`로 기록합니다. 정상 답변 저장의 응답이 유실됐다고 오류 답변으로 다시 덮어쓰지 않습니다.
- 먼저 선점된 작업을 건너뛸 수 있도록 대기 후보 20개를 살펴봅니다. 한 번에 분석 하나를 처리한 뒤 채팅에도 처리 기회를 줍니다. 전체 큐의 원자적 다음 작업 선점이나 서버 상시 운영을 대체하는 개선은 아닙니다.
- `node --test scripts/unit/ai.test.mjs`는 원문 근거·자료 구간·저장 응답 유실 처리를 외부 호출 없이 검사합니다.

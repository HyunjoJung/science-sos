# 로그인 없는 실제 AI 체험

`/try`는 방문자가 직접 작성한 과학 이유 문장을 Cursor CLI로 분석하는 별도 공간이다. `/demo`의 사전 작성 분석을 호출하거나 실패 시 대신 보여주지 않는다. 기존 학생 계정, 교사 비밀번호, 실제 학급 기록을 방문자에게 제공하지 않는다.

2026-09-20 확인 상태: 체험 전용 마이그레이션을 기존 Supabase 프로젝트에 단독 적용했다. 기존 학급 테이블과 미적용 학습 확장 마이그레이션은 변경하지 않았다. 로컬 브라우저에서 입력→Supabase 큐→실제 Cursor 결과→교사 역할 확인→관찰·설명 수정·새 사례를 완료했다. 외부 Vercel 프리뷰는 서버 비밀키 등록 승인 대기 중이며, 이 상태를 공개 AI 연결 완료로 표현하지 않는다. main과 원티드에 저장한 서비스 URL은 그대로다.

## 사용 흐름

1. 나무 80g·철 20g의 뜨고 가라앉음을 예측하고 이유를 1~300자로 작성한다.
2. 서버가 체험 전용 대기열에 입력을 저장한다. 전용 PC 워커가 실제 Cursor CLI를 한 번 호출한다.
3. AI가 제안한 가설, 입력에서 인용한 근거, 다음 확인 질문을 읽는다.
4. 방문자가 **교사 역할**로 가설을 확인·수정하거나 판단을 보류한다. 확인 전에는 반례 활동을 열지 않는다.
5. 조건을 비교하는 시뮬레이션을 관찰하고 설명을 다시 쓴 뒤 새 문항에 적용한다.

4~5단계는 역할 체험이며 실제 교사의 승인, 성적, 학급 저장 기록이 아니다. 분석 이후의 활동 결과는 해당 브라우저의 체험 상태다. 이름·연락처 입력을 요청하지 않는다.

## 연결 요건

- 웹 서버에 기존 Supabase URL과 **서버 전용** `SUPABASE_SECRET_KEY`가 필요하다. 비밀키는 `NEXT_PUBLIC_` 변수나 클라이언트 코드에 넣지 않는다.
- 새 `20260920114723_trial_ai.sql`만 체험 큐를 만든다. 기존 001~004나 미적용 005~007을 다시 실행할 필요가 없다. 개발·CI DB에서 통과한 동일 파일을 적용한다.
- Cursor에 로그인된 PC에서 `scripts/start-trial-worker.ps1` 또는 `node --env-file=.env.local scripts/trial-worker.mjs`를 실행한다. 기존 수업 워커와 PID·로그·작업 공간을 분리한다.
- 웹 배포만으로 AI가 실행되지는 않는다. 워커가 꺼져 있으면 화면에 오프라인 상태가 나타나고 새 요청은 503으로 거절된다. 온라인 표시는 최근 워커 통신을 뜻하며 개별 모델 호출 성공을 보장하지 않는다.
- main 반영 전에는 기능 브랜치의 Preview 환경만 구성하고, 서비스 제출 링크를 바꿀 때 실제 배포와 실제 모델 응답을 다시 확인한다.

## 접근과 호출 한도

브라우저에는 256비트 무작위 세션 쿠키만 제공한다. HTTPS에서는 `__Host-` 이름, Secure·HttpOnly·SameSite=Strict·Path=/와 24시간 만료를 사용한다. DB에는 토큰 원문 대신 SHA-256 해시를 저장한다. 조회 API는 쿠키 소유자의 최신 기록만 반환하고 해시·임대 토큰·내부 요청 키를 제거한다. 제출은 동일 Origin에서만 허용한다.

체험 테이블은 RLS를 켜고 `anon`·`authenticated`·PUBLIC의 권한을 회수한다. `SECURITY INVOKER` RPC를 서버의 service_role만 실행한다. 이 큐에는 기존 교실을 조회하거나 수정하는 기능이 없다. 서버 비밀키 자체는 프로젝트의 넓은 권한을 가지므로 신뢰하는 배포 환경에서만 사용한다.

DB 트랜잭션에서 세션당 하루 3회, IP당 하루 10회, 체험 전체 하루 50회, 동시 대기·처리 5건을 제한한다. 기존 교실의 하루 100회 예산과 별개다. 같은 요청 ID를 재전송해도 AI를 다시 호출하지 않는다. 새 요청 ID를 발급하는 수동 재시도는 한도를 사용한다. IP는 Vercel이 설정한 헤더만 신뢰하고 서버 비밀키로 HMAC 처리한다. Vercel 외 실행 환경에서는 임의 프록시 헤더 대신 공용 한도 묶음을 사용한다.

작업 임대가 만료되거나 모델 호출이 실패하면 오류 상태를 남긴다. 자동 유료 재시도는 하지 않는다. 완료 저장 응답이 유실되어도 모델을 다시 부르거나 성공 결과를 오류로 덮지 않는다. Cursor 도구 실행을 금지하고 서버 비밀키는 모델 프로세스 환경에서 제외한다. 모델 응답 스키마와 인용이 입력의 실제 부분 문자열인지 확인한 뒤 저장한다.

입력과 분석은 24시간 동안 조회할 수 있으며, 만료 기록의 정리는 워커가 실행 중일 때 수행한다. 이는 물리적 백업까지 즉시 삭제한다는 뜻이 아니다. 개인 정보나 실제 학생 정보를 체험란에 넣지 않는다.

## 확인 범위

- 단위 시험: 토큰·해시·신뢰 IP 경계, 모델 오류와 저장 응답 유실 처리.
- 일회용 PostgreSQL: 테이블/RPC 권한, 원자적 한도, 멱등성, 세션 격리, 임대·만료·원문 근거.
- 실제 HTTP 핸들러: 쿠키, 동일 Origin, 입력 크기, 요청·상태 조회, DB 영속 상태, 오류 코드.
- 실제 Cursor 호출은 별도의 합성 과학 문장으로 확인한다. CI의 대체 모델 응답은 실제 AI 성능 증거가 아니다.

참고: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Vercel 요청 헤더](https://vercel.com/docs/headers/request-headers).

보안 점검에서 새 체험 테이블 두 개의 RLS와 브라우저 역할 권한 회수, 네 RPC의 SECURITY INVOKER와 service_role 전용 실행을 확인했다. 새 테이블의 [RLS 정책 없음 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)는 브라우저에서 모두 차단하고 서버만 접근하도록 설계한 결과다. 기존 프로젝트의 다른 권한·인증 설정은 이번 체험 추가에서 변경하지 않았다.
